実効的拒否テスト 形式的な監督だけでは不十分です。LUMINA-30の事故レビューでは、不可逆化が発生する前に、正当な人間の拒否が実際に効力を持ち得たかを確認します。最小確認事項は、誰が拒否できたのか、情報・時間・権限があったのか、拒否すれば結果を実際に停止または遅延できたのか、推定同意・組織圧力・システム信頼度・事後正当化で拒否が置き換えられていなかったか、どの時点で拒否が効かなくなったかです。
事例から直接確認する このページは、具体的な導入、準事故、公開事例、事故をレビューする場合に直接使えます。Overviewは任意の背景資料です。AIに固定境界を読ませる場合はBoundary Kernel、文書全体を探す場合はIndex、理論背景を確認する場合は研究読書ガイドを使ってください。このページは実務レビュー入口であり、認証・承認の仕組みではありません。

このレビューで何を使ったか
  • Boundary Check — 不可逆化前の実効的人間拒否を中核境界として確認。
  • Incident Quick Assessment — 初期事実、時系列、影響、未確認点を整理。
  • Irreversibility Decision Criteria — 影響別にcandidate last reversible pointを検討。
  • Absence Rule — 公開証拠のない停止・再開権限を存在したと推定しない。
  • Result Classification — 証拠不足を含めて境界評価を分類。
  • Public-Source Review Template — FACT / UNKNOWN / INFERENCE / L30 ASSESSMENTを分離。
  • Actor–Authority–Evidence Mapping — 誰が何を知り、誰が実際に止められたかを分離。
  • Ordinary Incident Review Mapping — 通常の事故レビューとLUMINA-30追加視点を区別。

事故後に何を学ぶか

実施済み対策 → 誰が何をしたか

各ケースで、停止・封じ込め・資格情報失効・権限制限・修正・監視強化・通知・再開などを、実施主体と時系列に分けて記録します。

追加対策候補 → 何を防ぐためか

公開情報から合理的に検討できる追加策は、実施済み対策と分離して表示し、どの失敗経路を塞ぐための候補かを明記します。

対応主体 → 発見・STOP・復旧・再開・通知

AI企業、クラウド、ツール提供者、利用組織、監査主体などを分け、誰が発見し、誰が止め、誰が復旧し、誰が再開を承認したかを追います。

UNKNOWN → まだ分からないこと

内部ログ、実際の権限保持者、証拠到達時刻、反実仮想など、公開情報で確認できない事項は推測で埋めません。
